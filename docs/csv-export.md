# 历史记录 CSV 导出

0.6.0 起，记录页可将全部本机环境快照保存为 CSV，供电脑表格软件读取、分析和备份。导出读取已保存的记录，不请求和风 API，不定位，也不把缓存重新标记为新观测。0.7.0 已加入[历史筛选、对比与可选趋势](history-analysis.md)，**CSV 仍导出全部本机历史，不受区域或日期筛选及 A/B 选择影响**；筛选没有匹配但本机有记录时仍可导出。当前不支持 CSV 导入恢复、筛选 CSV 导出或传感器历史，文件格式仍为版本 `1`。

## 使用方式

1. 在底部“记录”页确认本机已有快照。全部历史为空或全部记录尚未成功加载时，导出入口不可用；当前筛选无匹配不等于历史为空。
2. 点击“导出 CSV”。App 整理当前全部快照后，打开 Android 系统保存窗口。
3. 选择“下载”等自己需要的位置，保留或修改建议文件名，再保存。
4. 返回 App，等待“已导出 … 份快照 · … 行数据”提示。快照数量和数据行数不同，因为每项指标占一行。

建议文件名为 `Ambient-history-yyyyMMdd-HHmmssZ.csv`，其中时间采用 UTC，末尾 `Z` 表示 UTC。系统保存窗口使用 `CreateDocument("text/csv")`，不新增存储权限；同名文件的处理由文档提供方决定。Android 自带保存窗口通常为同名文件添加编号，避免覆盖已有文档，见 [Android 文档存储说明](https://developer.android.com/training/data-storage/shared/documents-files)。

CSV 是明文，包含区域名称和用户备注，不包含天气凭据、私钥、经纬度或轨迹。App 不自动上传；如果在系统窗口中主动选择云文档提供方，文件可能按该提供方的规则同步。保存到 App 目录外的文档通常不会随卸载删除，具体取决于保存位置及文档提供方；本机数据库仍会在卸载或清除 App 数据后丢失。

CSV 目前只能供外部使用，不能导回 Ambient，不等同于可一键恢复的数据库备份。

## 文件格式

格式版本为 `1`，使用 UTF-8 BOM，便于常见 Windows 表格软件识别中文。表头与记录均使用 CRLF 换行，每个单元格均以双引号包围，单元格内的双引号写为两个双引号；逗号和换行留在引号内，参照 [RFC 4180 的 CSV 规则](https://www.rfc-editor.org/rfc/rfc4180.html)。不要通过按行切分或按逗号切分解析文件，应使用支持引用字段的 CSV 解析器。

每项指标占一行；同一快照的 ID、时间、区域、备注、归因及提示在各行重复，以便筛选和连接分析。记录按保存时间从新到旧导出，指标顺序与原快照一致。

| 列 | 内容 |
| --- | --- |
| 导出格式版本 | 当前固定为 `1`，供外部工具识别格式 |
| 快照ID | 本机记录的原 ID，相同 ID 的多行属于同一快照 |
| 区域 | 原快照区域名称 |
| 保存时间(UTC) | 本机写入记录的原 `Instant`，ISO 8601 UTC 字符串 |
| 数据获取时间(UTC) | 原快照成功获取的时间，保存缓存不会更新此值 |
| 观测时间(UTC) | 服务提供的独立观测时间；未提供则空白 |
| 缓存快照 | 保存时是否使用缓存，`true` / `false` |
| 演示快照 | 原快照的演示标记，`true` / `false`；正常保存规则禁止演示快照入库 |
| 备注 | 用户当前保存的备注 |
| 指标ID | 原指标标识，供外部工具区分指标 |
| 指标 | 原指标名称 |
| 数值 | 原显示值，缺失时保留 `—` 等原内容，不填 0 |
| 单位 | 原物理单位 |
| 数据来源代码 | `DEMO`、`DEVICE`、`REGIONAL_API` 或 `ESTIMATED` |
| 数据来源 | 对应“演示数据”“手机实测”“区域 API”或“算法估计” |
| 指标说明 | 原指标的物理含义与来源说明 |
| 风向来向角度(°) | 原风向角；未知时空白，不按文字风向推算 |
| 归因链接 | 原归因链接，多条以单元格内换行分隔 |
| 数据提示 | 原服务提示，多条以单元格内换行分隔 |

时间输出保留原有精度，统一以 UTC 的 `Z` 结尾；不会把获取时间填入未知观测时间。分析多次保存的缓存时，应按数据获取时间和缓存标记区分重复快照，不能把它们当作多次新观测。空指标快照如已存在，会保留一行元数据，而不是静默丢弃该记录。

为防止表格软件把备注、区域或说明误当作公式，文本首个非空白字符为 `=`、`+`、`-`、`@`，或原文以制表符、回车、换行开头时，导出会在内容前添加单引号。此保护只改变 CSV 中的文本，不修改本机记录；作为数值列的有效有限数值（例如负温度 `-5.2`）保留原值。外部程序直接读 CSV 时可能看到这个保护单引号，需要将其视为导出保护，不能据此修改原记录。

## 一致性与失败处理

- 准备阶段在 IO 调度器中进行。Room 事务内每批读取 64 条完整快照，逐条写入 App 私有缓存目录的临时 CSV，固定本次导出的数据；不一次把全部记录装进界面内存。
- 系统保存窗口只在 Activity 恢复到前台时启动，导出状态由 ViewModel 保留；旋转屏幕不会再打开第二个保存窗口。准备后发生的新增、删除或备注修改，不改变这一次已固定的内容，重新导出才会纳入变化。
- 用户选择保存位置后，后台复制临时文件。只有写入、刷新及关闭目标流全部成功，才报告导出完成；这代表文档提供方接受了写入，不保证云提供方此后已同步至服务器。
- 取消保存窗口会清理本次临时文件，保留全部源记录。失败同样不修改源记录，但目标位置可能留下空文件或不完整 CSV，界面会提示检查并删除后重试。
- 成功、取消和正常失败结束后清理当前临时文件。进程意外结束可能留下私有缓存文件；后续导出准备会清理超过一天且不属于活动导出的临时文件，系统也可回收缓存。
- 未改数据库表结构，schema 仍为 v1，未新增迁移或破坏性重建。历史记录、天气凭据和临时导出文件分别管理。

Debug 主 APK 和测试 APK 构建成功，**86 项单元测试、21 项 Android 仪器测试通过**；Android Lint 0 错误、5 条已有依赖版本提示。

- 单元测试涵盖 CSV 中文、引号、逗号、换行、单位、来源、原始时间、缺失值、负数与公式保护，以及导出冻结、临时文件清理和目标打开/写入/刷新/关闭失败。
