# 环境快照与历史记录

0.5.0 起可在首页保存当前区域环境，在记录页离线回看；0.6.0 新增[全部记录 CSV 导出](csv-export.md)，0.7.0 新增[区域/日期筛选、双快照对比与可选趋势](history-analysis.md)。保存对象是区域 API 已返回的数据；手机传感器与测速历史、连续采集和 CSV 导入恢复尚未实现。

## 使用方式

1. 在设置中完成和风配置，在总览页选择城市或使用当前位置，等待真实区域数据。
2. 点击“保存环境快照”，核对区域、数据获取时间和缓存状态；可填写最多 300 字备注，再确认保存。
3. 打开底部“记录”，按保存时间从新到旧查看区域、温度、AQI 和备注，点击记录查看完整详情。
4. 在详情中修改备注，或点击删除并再次确认。取消删除保留原记录；修改备注不改写原始环境数据和时间。
5. 点击记录页“导出 CSV”，在系统保存窗口选择文件位置，等待 App 提示导出完成。导出全部本机快照，每项指标一行；取消不会删除记录。

0.7.0 可按已保存区域名和手机本地获取日期筛选，含开始与结束当天，列表仍按保存时间排序。记录卡可选择最多两份快照作为 A、B，切换筛选保留选择；对比先保留原值与来源，符合条件时才计算 B − A。曲线另有可选入口，仅展示一个区域的零散获取数据，不代表连续采集；详细规则见[历史分析说明](history-analysis.md)。筛选无匹配不会隐藏已保存的其他记录，也不影响导出全部 CSV。

首次启动的演示数据不能保存，混入演示指标的快照同样会被拒绝。没有有效区域指标时无法保存。天气有效而空气暂缺时可以保存，缺失项仍保留 `—`，不以演示或旧空气数据补齐。刷新和定位期间暂停保存入口，避免保存尚在切换的数据。

## 时间与来源

| 字段 | 含义 |
| --- | --- |
| 保存时间 | 当前记录实际写入本机数据库的时间 |
| 数据获取时间 | 区域快照从服务成功获取的原始时间；保存缓存不会把它改成当前时间 |
| 观测时间 | 仅展示服务确实提供的独立观测时间；缺失时显示“服务未提供独立观测时间” |
| 缓存快照 | 保存时使用的是缓存数据；保留原获取时间，不能理解为刚刚发生的新观测 |
| 指标来源 | 保存原来源标签与说明；区域 API、手机实测、算法估计和演示不得互换 |

确认页固定打开时的快照，后续刷新不会替换这次待保存的数值。保存同时保留区域名称、指标值、单位、描述、缺失状态、风向角、归因和服务提示。列表显示温度与 AQI 摘要，详情按保存内容展示。记录不会随最新天气一起刷新，也不会因为天气凭据被清除而失去查看能力。

保存操作不额外发起 API 请求或定位。历史快照不保存经纬度或移动轨迹；区域名称仍可能反映个人活动地点。

## 本机存储与实现

- `domain/history` 定义快照草稿、记录、仓库接口、保存规则、日期范围、快照对比和趋势规则；不依赖 Room 或和风具体接口。
- `data/history` 使用 Room 2.8.5 / SQLite，KSP 2.3.12 生成访问代码。`ambient-history.db` 当前为 schema v1，结构导出在 `app/schemas/`，纳入版本管理，未开启破坏性迁移。
- `ui/history` 使用 ViewModel 与 StateFlow 处理列表、筛选、对比、趋势、详情和保存状态；页面只消费仓库契约。筛选和对比选择可在旋转时保留，结束进程后重置，不是长期保存的偏好。
- 通用 `data/environment/SnapshotCodec.kt` 用于序列化区域快照，天气缓存和历史复用同一模型，保留原时间与来源字段。
- 数据库读写及快照编解码在 IO 调度器执行。列表只查摘要，打开单条详情后才解码其完整快照；列表使用惰性布局，不为历史记录引入持续传感器监听或后台轮询。
- 每次保存采用一个固定 ID，整条记录一次写入。重复确认被界面拦截，同一草稿重试也不会重复插入或覆盖首次成功的内容、时间和备注。写入成功后才显示保存成功，失败保留待保存内容供重试。

数据库存放在 Android App 私有目录，**普通 SQLite 数据库尚未加密**。天气凭据与天气缓存另有 Keystore 加密存储，不代表历史数据库也已加密。

历史数据排除云备份和设备迁移备份。清除天气凭据与缓存、关闭区域 API 不删除历史；卸载 App 或清除 App 数据会删除历史。可将 CSV 保存到 App 目录外，用于外部读取、分析和备份；尚无导入恢复入口。CSV 为明文，含区域及备注，保存位置由用户决定。后续数据库升级需要显式迁移，并验证已有记录可以保留。

导出在 IO 调度器中的 Room 事务内按批读取，固定本次内容后才选择保存位置，取消及写入失败都不修改原记录。导出格式、临时文件处理和系统文件窗口行为见 [CSV 导出说明](csv-export.md)。

## 验证

以下为 **0.5.0 的历史验证记录**，保留当时测试结果与安装包校验值。0.6.0 CSV 导出验证另见 [CSV 验证记录](csv-export.md#验证)；0.7.0 的验证与安装包另见[历史分析说明](history-analysis.md#验证)。旧版计数和校验值不代替后续版本验证。

已通过 8 项 Android 仪器测试，使用专用 API 31 模拟器中的真实 Room / SQLite，覆盖：

- 缓存快照的原始获取时间、独立观测时间、来源、单位、缺失值、风向和归因往返保存。
- 同一草稿重复保存只保留一条记录，首次保存时间和内容不被覆盖。
- 按保存时间排序、只删除指定记录；备注长度限制、仅修改备注及记录不存在时的错误。
- 演示及混合演示数据被拒绝。
- 数据库关闭再打开后记录仍在。
- ViewModel 固定确认数据、忽略重复确认；失败保留草稿，重试成功后只写一次。

数据库测试使用独立临时测试库并在结束时清理，不清空正式历史库。全部 65 项单元测试通过，另覆盖保存规则、部分数据策略，以及“网络获取成功但缓存写入失败”的来源判定：新数据仍是本次获取，后续真正回退旧数据才标记缓存。

Debug 主 APK 与测试 APK 构建成功；Android Lint 0 错误、5 条已有依赖版本提示。

安装包：`dist/Ambient-0.5.0-debug.apk`，12,585,513 字节，APK v2 签名验证通过。

最终 APK 的 141 个解压条目及仓库候选文件均通过本机凭据检查，不含本机配置值或私钥。安装包与本地配置均被 Git 忽略。

