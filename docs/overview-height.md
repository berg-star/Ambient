# 总览近似定位高度 · 0.9.1

总览原海拔卡改为“近似定位高度”。启用区域数据后，点击“使用当前位置”，若 Android 的单次定位返回有效高度，就显示按米取整的读数。点击卡片可查看垂直精度、原定位时间及来源说明；缺失高度显示 `—`。室内或系统定位未提供高度时，无法保证取得读数。

这是系统定位报告的手机 **WGS84 椭球高度**，不是准确地形或平均海平面海拔。来源单列为 `POSITIONING`，正常显示“上次定位估计”，模拟位置显示“模拟定位”。不将其标成手机传感器实测或和风 API 数据。

## 显示规则

- 仅使用当前所选区域的单次设备定位高度；手选城市忽略手机高度，避免给另一城市套上本机高度。
- 正常报告的 0 米、负高度有效；缺失字段、非有限数及超出当前高度有效范围（−500 至 10,000 米）的值留空，不强制归零。
- 日光与天空使用的 0 米参考假设不会填入卡片。演示模式也不会制造高度数字。
- 天气失败但已取得有效区域位置时，仍可显示定位高度；不增加定位、天气请求、后台任务或采样频率。
- “刷新天气”不更新位置或高度。移动后需再次点击“使用当前位置”；每次定位仍沿用 30 秒超时、可用 GPS 时最多 5 秒高度等待，以及离页和后台取消。
- 旧版本保存的定位高度仍可显示；旧数据没有定位时间时明确标注“该次定位时间未记录”，不使用天气获取时间代替。

## 快照、缓存与 CSV

天气缓存保持原来的区域 API 内容。界面根据当前选区投影高度指标，不改写天气获取时间或服务观测时间。

保存环境快照时固定当时显示的高度、`POSITIONING` 来源、模拟标记以及含定位时间/精度的说明；这些内容随 JSON 保存在现有 Room schema v1。CSV 保持原 19 列，来源代码为 `POSITIONING`，定位时间和精度保存在“指标说明”列，模拟高度来源显示“模拟定位”。历史不保存经纬度或轨迹。

旧记录仍保持原指标和来源，不回填新的高度；旧 JSON 缺少模拟字段时按非模拟兼容读取。高度不加入区域天气趋势或差值计算，避免混淆不同基准。
